# 升级路线

当前目标：把 DeepPaper 整理为可以运行、解释和验证的学术文献 Research Agent 项目。

## 第一阶段：工程基线

- [x] 整理 README、架构、数据边界、开发和演示说明。
- [x] 配置固定 Node 环境、统一测试入口及 CI 工作流。
- [x] 明确保留版权及软件许可状态。
- [x] 将当前核心功能保存为本地提交，包含此前未跟踪的 Agent、RAG 和向量模块。
- [x] 完成自动检查、Windows 集成冒烟及打包验收，记录结果与限制。
- [x] 将文档、CI 和工程整理形成独立本地提交。
- [ ] 推送后观察 GitHub Actions 的首次真实运行结果。
- [ ] 录制真实数据演示并发布与源码对应的版本。

本地验证、远程 CI 和公开发布是不同验收项，不用其中一项代替其他项。

## 第二阶段：RAG 评测

- [ ] 完成 30-50 个问题的证据标注与 development/test 划分。
- [x] 实现关键词、纯向量和混合检索统一离线评测入口，并用合成样例验证。
- [x] 输出 Recall@K、MRR@K、精确/估算页码指标、检索延迟及失败案例；真实数值待标注数据。
- [ ] 在固定测试集上比较清洗、overlap 和 Chunk 长度。

详细设计见 [评测计划](evaluation.md)。

## 第三阶段：根据测量结果优化

- [ ] 优先解决评测暴露的漏召回、错误页码及重复证据问题。
- [ ] 评估本地多语言 Embedding，支持云端和本地两种运行方式。
- [ ] 根据实际延迟和内存决定是否引入嵌入式向量库。
- [ ] 完善 API Key 的系统级安全存储、IPC 校验及桌面运行时升级。

## 第四阶段：Agent 可靠性

- [ ] 严格的工具参数 schema、执行记录、取消和重试边界。
- [ ] 中断恢复与人工确认状态持久化。
- [ ] 多轮检索与证据补充任务的成功率评测。
- [ ] 依据流程复杂度决定是否引入 LangGraph；追踪数据默认留在本地。

## 简历描述原则

可以描述现有的页级清洗、混合检索、向量缓存、JSON 工具协议和引用回跳。尚不能写“已接入 LangChain/FAISS”“使用原生 Function Calling”“完全离线”“生产级高并发”或没有测量依据的百分比提升。

项目名称建议使用“DeepPaper：本地优先的学术文献 Research Agent”。后续简历亮点应附上自己的设计取舍、可复现指标及失败案例。
